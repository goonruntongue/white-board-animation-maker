# 3. AI に作業させる

コネクターがつながったら、AI にホワイトボード動画を作らせます。
Codex と Claude で同じ指示文を使うと、出来を比べやすくなります。

---

## 準備：画像をアプリに読み込む（人が行う）

1 で作った画像を、**自分でアプリに読み込みます**。

- PC：画像をアプリの画面にドラッグ＆ドロップするか、メニューの「画像を読み込む」
- スマホ：メニューの「画像を選ぶ」

> **なぜ人が読み込むのか：** AI が画像を道具に渡すには、画像を百万文字以上の文字（base64）に変えて書き出す必要があり、現実的ではありません。
> 画像がインターネット上にあり、ほかのサイトから読み込める場所（GitHub の raw の URL など）にあるときは、指示文の中で「load_image に url としてこの URL を渡して」と頼む方法もあります。

---

## 作業させる指示文（Codex・Claude 共通）

次をそのまま送ります。

```text
「whiteboard」（Whiteboard Animation Maker）の MCP ツールを使って、
アプリに読み込んである画像から、人がホワイトボードに手で書いているように見える動画を作り、MP4 で書き出してください。

このアプリは、画像を隠しておき、ペンを持った手がなぞった所から見えていく「描いていく動画」を作ります。
動画は「グループ」の並びでできていて、各グループは1本以上の線（ペン先が通る点の並び）を描き順どおりに描きます。
操作はアプリの画面にそのまま表示され、私が見ています。

## 進め方
1. get_status で状態を確かめる。画像がなければ、そこで止めて私に知らせる
2. get_image（max_width 1024）で絵をよく見て、何がどこに描かれているか（タイトル・見出し・本文・絵・矢印など）を把握する
3. auto_trace（mode: natural）で下書きを作る
4. list_groups と get_image（show_groups: true）で、どのグループが絵のどこかを確かめる
5. 「人が書く自然さ」になるよう直す（下の「自然さの基準」）
   - 並べ替え：reorder_groups
   - 時間・間：update_group（duration_ms・delay_after_ms）
   - 書き順が不自然な文字や、まとまりが悪い所：get_group で線を見てから、update_group の parts で描き直すか、add_group で1画ずつ作り直し、元のグループは delete_groups で消す
   - 細かすぎるグループは merge_groups でまとめる
6. render_frame で途中のコマ（progress 0.25・0.5・0.75・1.0）を見て、変な所があれば直す
7. export で mp4（max_width 1280）を書き出す。続けて project（編集用）も書き出す
8. 最後に「報告の形」にそって報告する

## 自然さの基準
- 順番：人が説明しながら書く順にする。基本は、タイトル → 上から下・左から右。ひとまとまり（見出しと、その絵）を書き終えてから次へ移る
- 文字：日本語の書き順（横画が先・上から下・左から右 など）を守る。1文字の中で手があちこちに飛ばないようにする
- 絵：輪郭を先に、中の細かい所や塗りはあとに
- 矢印・下線・囲みなどの飾りは、それが指す内容を書いたあとに
- 速さ：文字は1文字 0.4〜0.8 秒くらい。大きなタイトルは少しゆっくり、本文の小さい文字は速めに。絵は形の大きさに合わせる
- 間：同じまとまりの中は 0.1〜0.3 秒、まとまりが変わるときは 0.5〜1.0 秒
- 全体の長さ：30〜60 秒くらいを目安にする（長すぎる場合は、間や速さで調整する）

## 守ること
- 座標はすべて元の画像のピクセル（左上が 0,0）。get_image の縮小画像の座標ではなく、元の大きさに直して使う
- 大きく直す前には、何をどう変えるかを1〜2行で私に知らせてから進める
- うまくいかない操作は、同じことを3回以上くり返さない。止めて状況を知らせる
- 間違えたときは undo で取り消せる

## 報告の形
- 直したこと（順番・書き順・時間など）を箇条書きで
- 動画の長さ
- MP4 と編集用プロジェクトのダウンロード URL（2時間有効）
- 自信がない所・直しきれなかった所
- このアプリの道具（MCP ツール）で、足りなかったこと・使いにくかったこと
```

---

## うまくいかないとき

- **「アプリが開いていません」と言われる**：アプリのタブを開き、「AI 連携（MCP）」の受け付けがオンになっているかを確かめる
- **途中で止まる・時間がかかる**：MP4 の書き出しは、作品の長さによって数十秒〜数分かかります。アプリのタブを裏に回さず、そのまま待ちます
- **作業が長くなりすぎる**：「残りは順番と時間だけ直して、書き出しまで進めて」と伝えると早く終わります

---

## 比べるときのメモ（Codex と Claude）

| 見る所 | Codex | Claude |
|---|---|---|
| 最後まで（書き出しまで）たどり着いたか | | |
| かかった時間・道具を使った回数 | | |
| 順番は自然か（タイトル→上から下・左から右） | | |
| 日本語の書き順は正しいか | | |
| 速さ・間は自然か | | |
| 途中の報告は分かりやすかったか | | |
| AI が挙げた「足りない道具・使いにくさ」 | | |

AI が挙げた「足りない道具・使いにくさ」は、アプリの MCP の道具を直すときの手がかりになるので、控えておいてください。
