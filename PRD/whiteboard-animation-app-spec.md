# ホワイトボード・アニメーション生成アプリ 設計仕様書

## 1. 目的

ホワイトボードの清書画像（PNG / JPEG）を読み込み、ペンを持つ手が画面上を移動しながら、内容を少しずつ描き出していくように見せるアニメーションを作る。

完成物は、ブラウザでそのまま再生できる単一HTMLと、必要に応じてMP4 / GIFとして出力できることを目標にする。初期版ではビットマップ画像を対象とし、SVGは将来の上位機能とする。

## 2. 基本アイデア

元画像を最初は完全に隠し、ペン先が通った範囲だけを徐々に表示する。画像そのものを線へ変換しなくても、「手が描くにつれて完成図が現れる」表現を実現する。

```
完成画像 ──> 表示用マスク ──> ペン先の軌跡でマスクを削る ──> 見える範囲が増える
                                  └─> 同じ座標に手・ペン画像を配置
```

## 3. 初期版の利用フロー

1. 利用者がホワイトボード清書画像をアップロードする。
2. アプリが画像の縦横比に合わせたキャンバスを作る。
3. 利用者が「描く道筋」をマウスまたは指でなぞる。
4. 道筋ごとに、速度・ペンの太さ・待機時間を調整する。
5. 再生して確認し、必要なら道筋を編集する。
6. 単一HTML、または動画・GIFとして書き出す。

## 4. 画面構成

| 領域 | 内容 |
| --- | --- |
| プレビュー | 白いホワイトボード、描画中の画像、手・ペンを重ねて表示 |
| 素材設定 | 元画像、手の種類、ペン画像、ペン色、影の有無 |
| 軌跡編集 | 描き順の追加、選択、削除、並び替え、再録画 |
| 再生設定 | 全体速度、各軌跡の速度、開始前・途中・終了後の待機時間 |
| 出力 | HTML、MP4、GIFの書き出し |

## 5. 描画データの考え方

### 5.1 元画像

- 初期版の入力形式：PNG、JPEG、WebP
- 推奨：白背景・高コントラスト・1920×1080以下
- 透明PNGも許可し、下に白いホワイトボード背景を敷く

### 5.2 軌跡

1本の軌跡は、時刻付きの座標列として記録する。

```js
{
  id: "stroke-01",
  points: [
    { x: 120, y: 220, t: 0 },
    { x: 125, y: 224, t: 32 }
  ],
  revealWidth: 28,
  duration: 2200,
  delayAfter: 300
}
```

- `x`, `y`：画像の基準サイズに対する座標
- `t`：手でなぞったときの時刻。残せば手書きらしい速度変化を再現できる
- `revealWidth`：マスクを消す太さ。文字や図より少し太めにする
- `duration`：再生時間。初期版では均一速度でもよい

### 5.3 手・ペン素材

- 透過PNGまたはWebPを利用する
- ペン先の位置を素材内の基準点として登録する
- 軌跡の移動方向から角度を計算して、手素材を回転・移動する
- ペン色を変える場合は、ペン画像を色替えするか、ペン先に色線を重ねる

## 6. 描画・再生の技術方針

Canvasを3層に分ける。

1. **背景層**：白いボード、必要なら紙目や枠
2. **画像層**：完成画像を描画
3. **マスク／手の層**：黒で覆ったマスクを軌跡に沿って消し、手素材を重ねる

実装では、完成画像を描いたCanvasに対して、軌跡部分を `destination-out` で消す方式が分かりやすい。消えた箇所から下の完成画像が見え、ペン先の近くに手を描けば「描いている」ように見える。

アニメーションは `requestAnimationFrame()` で進める。各フレームで現在時刻に対応する軌跡の地点までマスクを更新し、手の位置と角度を描く。

## 7. 出力仕様

### 7.1 単一HTML（優先）

- HTML、CSS、JavaScript、画像データを1ファイルに内包する
- インターネット接続なしでブラウザ再生できる
- 再生・一時停止・先頭へ戻るボタンを付ける
- HyperFramesのようなHTMLスライドへ埋め込みやすい
- サイズ削減のため、画像はWebP化・適度な解像度制限を選択可能にする

### 7.2 MP4

- Canvasの `captureStream()` と `MediaRecorder` を利用する
- ブラウザによってはWebM出力が中心になるため、MP4変換は将来機能または外部変換とする

### 7.3 GIF

- 短いループ用途向け
- 色数とファイルサイズが増えやすいため、基本はHTMLまたは動画を推奨する

## 8. MVP（最初に完成させる範囲）

- PNG/JPEGを1枚読み込める
- マウスで複数の描画軌跡を登録できる
- 軌跡順に画像を出現させられる
- 透過の手・ペン画像がペン先に追従する
- 再生、停止、最初から再生
- 単一HTMLとしてダウンロード

この時点で、ホワイトボード清書データを説明用アニメーションスライドに変える目的は達成できる。

## 9. 後から加える機能

- 軌跡を自動提案する画像解析
- AIによる「文字→図→補足」の描き順案
- 軌跡のベジェ曲線編集、消しゴム、部分的な描き直し
- 手やペンの素材セット
- ナレーション、効果音、テロップ
- テンプレート（16:9、9:16、1:1）
- SVG読み込み：パス単位でより正確な描画順を制御
- SVGの線描きアニメーション：`stroke-dasharray` / `stroke-dashoffset` を活用
- WebM / MP4の高品質書き出し

## 10. 注意点と判断

| 論点 | 初期版の判断 |
| --- | --- |
| ビットマップからSVGへの自動変換 | 行わない。自然な描き順の自動推測は難しいため |
| 描き順 | 利用者がなぞって指定する。精度と操作性のバランスがよい |
| 画像を見せる幅 | ペン線より少し太くして、画像の欠けを防ぐ |
| 手書き感 | 軌跡をなぞった時間情報を保存し、均一速度にしすぎない |
| 出力の優先順位 | 単一HTMLを最優先。動画は副次出力 |

## 11. 成功条件

村上さんの清書画像を読み込み、数分の操作で「手が描いているようにホワイトボードが完成するHTML」を作り、ネット接続なしで他者のPCでも再生できること。

## 12. 開発ロードマップ

### フェーズ1：ブラウザ版で核を検証する

最初の試作は、ブラウザで動くHTML / CSS / JavaScriptアプリとして作る。対象は、**画像1枚・手素材1種類・軌跡編集・HTMLダウンロード**に絞る。

検証する合格条件は次の3点。

1. 画像の出現が「手で描いている」と自然に感じられること
2. 軌跡編集が、清書データを作る作業の流れを妨げないこと
3. ダウンロードした単一HTMLが、ネット接続なしで別のPCでも再生できること

この段階では、Electron固有のファイル処理やインストーラー作成は行わない。Canvas、マスク、手の追従、HTML出力という核が正しいかを先に確認する。

### フェーズ2：実データで検証し、合格判定する

村上さんの実際のホワイトボード清書データを数件使い、生成物を確認する。描き順、文字や図の欠け、手の位置、出力HTMLの容量を調整する。

ここで「普段の制作に使える」と判断できたら、ブラウザ版の仕様を固定する。動画書き出しやSVG対応は、この時点では追加しない。

### フェーズ3：Electron版へ移植する

検証済みのブラウザ実装を、ElectronでWindowsデスクトップアプリとして包む。

- 画像をドラッグ＆ドロップで読み込む
- 保存場所をOSのダイアログで選ぶ
- 単一HTMLや動画をローカルへ保存する
- ネット接続なしで使用する

ブラウザ版でCanvas部分を先に合格させるため、Electron版は「新たに作り直す工程」ではなく、制作ツールとして使いやすくする工程になる。

### フェーズ4：上位機能を追加する

Electron版を日常利用して必要性が確認できたものだけ、動画書き出し、AIによる描き順提案、SVG対応、素材セットなどを追加する。
